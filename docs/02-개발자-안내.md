# 개발자 안내

사용자용 설명은 [README](../README.md), 설계와 결정 기록은 [01-설계안.md](01-설계안.md).
여기는 **만들고 검사하고 내는 법**만 적는다.

## 구조 한 장

```
src/            React + TypeScript (Vite)      화면 · pdf.js 추출/뷰어 · IPC 껍데기
src-tauri/      Rust (Tauri 2 + rusqlite)      저장 · 검색(FTS5 + 벡터) · 답변 파이프라인 · 검증 · 기록
test/pdf/       추출 시험용 PDF (fixtures)
test/search/    청크 fixture (검색 시험)
test/golden/    실제 업무자료 3종 · 골든 셋 67문항 · 벡터(.bin) · LLM 답 갈무리
scripts/        검사 스크립트 · UI 자동화(ui/) · 골든 셋 도구
```

**AI 는 이 PC 의 Ollama(127.0.0.1:11434)하고만 이야기한다.** `ureq` 를 TLS 없이 빌드해
바깥으로 나갈 길이 없고(`ai/ollama.rs` 의 `guard`), CSP 의 `connect-src` 도 그 주소만
허용한다. pdf.js 의 cMap·글꼴·wasm 은 `public/pdfjs/` 로 복사해 앱 안에서 읽는다
(`scripts/copy-pdfjs-assets.mjs`, `npm run dev/build` 앞에 자동).

## 필요한 것

- Node.js 22 이상 (24 로 개발) · Rust stable · Visual Studio Build Tools (C++ 데스크톱)
- 실행·검사에 Ollama 는 **필요 없다.** 골든 셋 벡터와 LLM 답이 갈무리되어 있어 검색·답변
  평가가 Ollama 없이 돈다. 갈무리를 새로 만들 때만 필요하다.

## 실행

```bash
npm install
npm run app            # 개발 실행 (실제 자료 폴더 %APPDATA%\kr.school.docaid)
npm run app:sandbox    # 연습용 — identifier 가 달라 자료가 따로 저장된다. 지우는 시험은 여기서
```

## 검사 — 한 번에

```bash
npm run check:all
```

| 검사 | 무엇을 막나 |
|---|---|
| `check:model` | 세 파일 버전 어긋남 · 산출물 이름에 한글 (릴리스가 조용히 깨진다) |
| `check:updater` | tauri.conf 의 pubkey ≠ 서명 키 · endpoint ≠ 저장소 · 빌드된 설치 파일의 .sig 가 pubkey 로 검증되지 않음 · latest.json 꼴 · 버전 견주기 |
| `check:pdf` | 원문 문장 → 추출 텍스트 → 쪽 → 문자 위치가 어긋남 (**가장 중요**) |
| `check:chunk` | 청크가 가리키는 자리가 pdf.js 항목으로 이어지지 않음 (형광펜의 근거) |
| `check:golden` | 골든 셋 정답 문장이 실제 PDF 그 자리에 없음 |
| `build` | 타입 오류 · 화면 빌드 |
| `cargo test --lib` | 마이그레이션(백업·**downgrade 보호**) · 낱말/뜻/섞기 검색 · 인용·숫자·주장 검증 · 거부 · 초점 낱말 · 작업 기록 · **골든 셋 검색 품질** · **P5 답변 평가**(갈무리된 답) |

CI(`.github/workflows/check.yml`)도 같은 검사를 같은 차례로 돈다. 추가로 "내보낸 청크가
최신인가" 를 본다 — 청크 규칙을 고치고 `npm run fixtures:chunks` · `npm run golden:analyze`
· `npm run golden:build` 를 돌려 커밋하지 않으면 시험이 옛 청크를 보며 통과하기 때문이다.

### 검색·답변 평가만

```bash
npm run golden:eval                                   # 검색 세 방식 + 답변 평가 (갈무리)
cd src-tauri && cargo test --lib eval::answer -- --nocapture
DOCAID_EVAL_MODEL=qwen3:8b cargo test --lib eval::answer -- --nocapture   # 모델을 바꿔서
```

갈무리: `test/golden/vectors/*.bin`(청크·물음 벡터), `test/golden/answers/<모델>/*.json`
(LLM 답, 물음+근거의 지문이 같으면 다시 묻지 않음). 지우면 Ollama 로 몇십 분~몇 시간을
다시 기다려야 한다. 오래 도는 평가는 `CARGO_TARGET_DIR=src-tauri/target-eval` 로 따로
빌드하면 본 target 의 시험 exe 와 충돌하지 않는다 (폴더는 .gitignore).

## UI 자동화

`scripts/ui/*.ps1` — Windows UI Automation 으로 앱을 사람 손 없이 누르고 읽는다
(`dump.ps1` · `click-text.ps1` · `paste.ps1` · `pick-combo.ps1` · `pick-file.ps1` ·
`capture.ps1` · `window.ps1` · `net-check.ps1` · `net-watch.ps1`). 스크립트 본문은 ASCII 만 — 한글은
UTF-8 파일로 넘긴다. 화면이 잠기면 클릭·입력이 안 되고(dump 는 됨), 화면 밖 요소는
`window.ps1 -ScrollAt` 로 스크롤한 뒤 눌러야 한다. 자세한 것은 `scripts/ui/README.md`.

## 이름 규칙

**빌드·배포·파일 시스템에 닿는 이름은 전부 영문, 사용자에게 보이는 이름만 한글.**

| 자리 | 값 |
|---|---|
| `productName` · 설치 파일 | `DocAid` |
| identifier · 자료 폴더 | `kr.school.docaid` (연습용 `kr.school.docaid.sandbox`) |
| 저장소 | `lohemal/document-ai-assistant` |
| 창 제목 · 화면 | 업무자료 AI 도우미 |

## 자료구조 올리기

`src-tauri/src/db/schema.rs` 의 `MIGRATIONS` 에 **덧붙이기만** 한다(지금 V4). 앱은 열 때
`PRAGMA user_version` 을 보고 모자란 것을 차례로 올리며, 올리기 전에 `backups\pre-migration-vN-…db`
를 만든다. 자료가 프로그램보다 새것이면 **아무것도 하지 않고** "최신 버전으로 업데이트"
안내로 멈춘다 (`db/mod.rs::migrate`, 시험 `db::tests`).

## 설치 파일 만들기

```bash
# 서명 키 없이 (설치 파일만 확인할 때)
npm run app:build:nosign

# 서명까지 (릴리스와 같은 산출물). 키는 저장소 밖 %USERPROFILE%\.docaid-release\docaid.key
TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.docaid-release/docaid.key)" TAURI_SIGNING_PRIVATE_KEY_PASSWORD="" npm run app:build
npm run check:updater   # 만든 .sig 가 pubkey 로 검증되는지까지 본다
```

산출물: `src-tauri/target/release/bundle/nsis/DocAid_<버전>_x64-setup.exe` (+ `.sig`).
NSIS · 현재 사용자 설치(관리자 권한 없음) · 한국어. 코드 서명 인증서는 없다 —
SmartScreen 경고는 알려진 한계다.

## 새 버전 내기

```bash
npm run version:set 0.2.0
npm run check:all
git add . && git commit -m "v0.2.0"
git tag v0.2.0 && git push origin main --tags
```

`릴리스 만들기`(release.yml) 가 검사 → 빌드 → 서명 → `latest.json` · `SHA256SUMS.txt`
→ GitHub Release 를 한다. 시크릿은 `TAURI_SIGNING_PRIVATE_KEY` **하나만** 넣는다
(`…_PASSWORD` 는 넣지 않는다 — 워크플로가 빈 문자열을 넘긴다).

> 업데이터 서명 키를 잃으면 이미 설치된 프로그램에 업데이트를 보낼 수 없다.
> 키가 바뀌었으면 `tauri.conf.json` 의 `pubkey` 도 같이 바꿔야 하고, `check:updater` 가 어긋남을 잡는다.

## 오프라인 검증 (릴리스 전)

설치한 앱의 아웃바운드를 막고 전 기능을 돈다 (설계안 10-6).

```powershell
New-NetFirewallRule -DisplayName "DocAid-offline-test" -Direction Outbound `
  -Program "$env:LOCALAPPDATA\DocAid\DocAid.exe" -Action Block
# … PDF 등록 · 원문 · 낱말/혼합 검색 · 규정 해석 · 문서 작성 · 작업 기록 …
Remove-NetFirewallRule -DisplayName "DocAid-offline-test"
```

루프백(127.0.0.1 Ollama)은 방화벽에 걸리지 않으므로 AI 도 그대로 된다. 연결 목록은
`scripts/ui/net-check.ps1` 로 프로세스별(DocAid.exe / msedgewebview2.exe)로 적는다.

방화벽 규칙은 관리자 권한이 있어야 한다. 없으면 Wi‑Fi 를 끊은 뒤 아래를 뒤에서 돌려 두고
전 기능을 돈다 — 앱과 자식 프로세스의 TCP 연결을 2초마다 표본으로 떠서 CSV 로 남긴다.
루프백 밖 주소가 한 줄이라도 있으면 실패다.

```powershell
powershell -File scripts/ui/net-watch.ps1 -Seconds 600 -Out net-offline.csv
```

P8 에서 인터넷이 연결된 채로 7분 떠 본 결과는 `127.0.0.1:11434` 와, [업데이트 확인] 을
눌렀을 때의 `github.com:443` 한 번뿐이었다 (설계안 10-8).
